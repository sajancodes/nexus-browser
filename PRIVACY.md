# NEXUS Privacy Specification & Architectural Blueprint

**Version:** 0.1.0  
**Status:** Living Architectural Specification  

NEXUS is engineered under the assumption that privacy must be enforced at the compiler, engine, network, and storage levels. Privacy is not a toggled setting or a marketing promise; it is the structural baseline of the software.

---

## 1. What Information NEXUS Stores

All data generated by the user or the browser engine remains local to the device by default:

- **Local Profile & Preferences:** User configuration options (e.g. active cookie policy mode) stored in JSON/SQLite format.
- **CEF Engine Caches:** Temporary HTTP disk cache and shader cache generated by Chromium under the application's private directory.
- **Session State:** Tab titles, URLs, and active tab identifiers managed in process memory during runtime.
- **Privacy Event Counters:** Real-time metrics counting blocked cookies, stripped referrers, denied permissions, and rejected popups. These counts are stored in volatile memory and exposed via the Privacy Dashboard.
- **Planned for Milestone 2 & 3:** Structured browsing history, bookmarks, site permissions, and custom filter rules stored in indexed local SQLite databases.

---

## 2. Where Information Is Stored

By default, NEXUS stores all runtime files and profile data in an isolated, user-controlled location on the local file system:

- **Windows:** `%LOCALAPPDATA%\NEXUS\`
  - `profile/preferences.json` — User preferences and privacy mode.
  - `cef/cache/` — Chromium HTTP cache and network state.
  - `logs/` — Local runtime diagnostics (only written when `NEXUS_CEF_LOG=1` is set).
- **Custom Location:** Users may redirect all storage at launch using the `--user-data-dir=<path>` or `--nexus-user-data-dir=<path>` flags, or via the `NEXUS_USER_DATA_DIR` environment variable.
- **Root Prohibition:** NEXUS explicitly refuses to use a filesystem root directory (e.g. `C:\`) as a data directory to prevent accidental data corruption or privilege escalation.

---

## 3. What Information NEXUS Transmits

**NEXUS transmits zero telemetry.**

Under no circumstances does NEXUS transmit:
- Browsing history, URLs, or search queries to NEXUS servers.
- Crash dumps or error reports.
- Usage metrics, session recordings, or feature engagement telemetry.
- Hardware fingerprints or device identifiers.
- Advertising identifiers or unique installation IDs.

NEXUS does not operate any telemetry ingest endpoints. There are no background analytics pings.

---

## 4. External Services Contacted

NEXUS minimizes outbound connections. The only network connections made are:

1. **User-Initiated Navigation:** When the user enters an address or clicks a link, the browser connects to the requested destination server over HTTP/HTTPS.
2. **Search Queries:** Searches submitted via the address bar query DuckDuckGo (`https://duckduckgo.com/?q=...`). No search suggestions or keystroke logging are sent while typing.
3. **Future Planned Updates (Milestone 3+):** Filter list updates (e.g. EasyList/Brave Adblock) will periodically fetch verified, public static rule lists over HTTPS directly from authorized upstream distribution CDNs. These downloads contain no user identifiers.

---

## 5. Cookie Architecture & Policy Engine

NEXUS provides deep cookie isolation integrated with `CefCookieAccessFilter`.

### 5.1 Cookie Modes

- **Strict Mode (Default):**
  - All cookie access is denied (`ShouldAllowCookie` returns `false`).
  - Web applications cannot read or write first-party or third-party cookies.
  - Referrers are stripped completely (`REFERRER_POLICY_NO_REFERRER`).
  - Designed for maximum privacy during search and read-only browsing.
- **Balanced Mode:**
  - Third-party tracking cookies are strictly blocked.
  - Temporary first-party cookies matching the top-level origin are permitted for authentication and essential session state.
  - Cross-origin referrers are reduced to the origin (`REFERRER_POLICY_ORIGIN_ONLY_ON_TRANSITION_CROSS_ORIGIN`).
- **Session Cleanup:**
  - `CefSettings.persist_session_cookies = false` ensures that session cookies are not persisted across browser launches.
  - Users can trigger immediate cookie purge via the Privacy Dashboard (`privacy.clearCookies`), invoking `CefCookieManager::DeleteCookies`.

## 6. Anti-Fingerprinting Strategy

Browser fingerprinting exploits combinations of hardware, graphics, audio, fonts, and API behaviors. NEXUS approaches fingerprinting through defense-in-depth:

1. **Standardized Engine Parameters:** Built on Chromium 156 with consistent engine attributes.
2. **Deny-by-Default APIs:** Intrusive hardware and sensor APIs (Web Bluetooth, WebUSB, Web MIDI, Web Serial, Gyroscope, Accelerometer) are permanently disabled.
3. **WebRTC Leak Prevention:** Content clients restrict WebRTC IP leakage to default route interfaces, preventing discovery of local LAN IP addresses.
4. **Honest Architectural Scope:** NEXUS does not claim total immunity to fingerprinting. Superficial JavaScript spoofing often increases uniqueness; NEXUS prioritizes standardizing Chromium engine responses and eliminating sensitive APIs.

---

## 7. Private Browsing Architecture

Private browsing (Milestone 3 / 7) enforces absolute disk isolation:
- Operates in a distinct, ephemeral `CefRequestContext` with in-memory cache (`cache_path` left empty).
- No browsing history, cookie records, or cache entries are written to SQLite or disk.
- Exiting the private window immediately purges the ephemeral context from memory.
- Does not affect normal profile data.

---

## 8. Network Privacy & WireGuard VPN Architecture

- **OS-Level WireGuard Integration (Milestone 6):** Uses genuine kernel-level or OS-level WireGuard networking (via WinTun / WireGuard-NT on Windows), routing IP traffic through authenticated tunnels.
- **No Pseudo-Proxy:** NEXUS does not repackage an HTTP proxy as a "VPN".
- **DNS-over-HTTPS (DoH):** Configurable secure DNS resolvers prevent ISP-level DNS snooping.
- **Kill-Switch:** Network routes drop traffic if the WireGuard tunnel unexpectedly disconnects.

---

## 9. What Websites Can Still Observe

Privacy tools cannot alter fundamental network realities. Even with NEXUS protections:
- **Destination Servers:** The website you visit observes your public IP address (unless a VPN is active), the time of connection, and any data you submit in web forms.
- **Network Operators & ISPs:** Without a VPN, your ISP can observe the IP addresses and SNI domain names of HTTPS connections you establish.
- **VPN Providers:** If you connect through a WireGuard VPN tunnel, your VPN provider observes your public IP and destination server IPs.

---

## 10. Data Deletion & Erasure Limits

- **Complete Data Purge:** Users can wipe all local browser records by deleting `%LOCALAPPDATA%\NEXUS` (or triggering "Clear All Data" in settings).
- **Physical SSD Limits:** Deleting database records or cache files updates filesystem metadata. Due to solid-state drive (SSD) wear-leveling algorithms, write amplification, and TRIM latency, NEXUS cannot guarantee immediate physical erasure of NAND flash cells without OS-level disk encryption (e.g. BitLocker/LUKS).
